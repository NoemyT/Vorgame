# Vorgame — Relatório de Testes

## 1. Objetivo e escopo

Registrar a validação da versão final do protótipo, contemplando HU01 a HU05, infraestrutura e funcionalidades complementares. A HU06 (reviews) permanece fora do escopo. As evidências consistem nas saídas de terminal fornecidas pela equipe, no checklist de aceite em produção preenchido pelo responsável pelos testes e nos registros históricos do projeto.

## 2. Ambiente e ferramentas

- Execução automatizada: 27/11/2026, Windows, PowerShell, versão final do repositório.
- Backend: Vitest 4.1.12, Supertest, cobertura V8, ESLint, Oxlint e Nest CLI.
- Frontend: Vitest 5.1.1, React Testing Library, Oxlint, TypeScript e Vite 8.3.8.
- Aceite manual: aplicação publicada em [Vercel](https://vorgame.vercel.app), API no Render, banco TiDB Cloud e catálogo IGDB. Realizado após os testes automatizados; horário exato não informado.
- Identificador do commit testado e versões locais de Node.js e npm não informados.

## 7. Evidências históricas de persistência e integração

Conforme o [Modelo de Dados e Seed](8.%20Modelo%20de%20Dados%20e%20Seed.md):

| Validação | Resultado registrado |

| Migration aditiva em MariaDB isolado | Preservação de jogos, IDs e avaliação preexistente |

| IGDB simulada com MariaDB | Preservação do vínculo, avaliação e metadados |
| IGDB real com Terraria e MariaDB | Busca, detalhes, criação e alteração de nota; nova busca preservou ID e agregados |
| Migration `20261127223303_identidade_externa_jogo` no TiDB Cloud | Aplicação bem-sucedida confirmada pelo responsável pelo banco após correção |

Essas evidências são históricas e não foram contabilizadas entre os 195 testes automatizados nem entre as 24 verificações manuais atuais.

## 8. Limitações e conclusão

- A concorrência de gravações de avaliações no TiDB compartilhado não foi comprovada por teste específico nesta revisão.
- A restrição SQL `CHECK` para notas de 0 a 10 não integra as migrations finais; a API valida o intervalo.
- A cobertura dos limites de qualidade do AGENTS.md pelo linter do frontend é incompleta.
- O checklist manual não contempla todos os cenários de exceção, como indisponibilidade real da IGDB, nem constitui auditoria completa de acessibilidade, segurança ou desempenho.
- Não foram fornecidos logs integrais de requisições em produção, capturas de tela ou hash do commit testado. As saídas de terminal e o checklist fornecidos pela equipe fundamentam este relatório.

A versão final apresentou 195/195 testes automatizados aprovados, 24/24 verificações manuais aprovadas, linters sem erros ou avisos e builds sem falhas reportadas. Os resultados sustentam o aceite dos fluxos principais de HU01 a HU05 e das funcionalidades complementares verificadas, respeitando as limitações acima. A HU06 permanece adiada.
