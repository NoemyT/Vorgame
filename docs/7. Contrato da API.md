# Vorgame — Contrato da API

Este contrato define os endpoints do backend para o protótipo desta entrega (HU01 a HU05), conforme o recorte registrado nas [histórias de usuário](1.%20Hist%C3%B3rias%20de%20Usu%C3%A1rio%20%28Alta%29.md) e a stack do [ADR-002](2.%20ADR.md). A implementação em NestJS deve seguir este documento; a documentação gerada por `@nestjs/swagger` deve ser conferida com ele.

## Convenções gerais

| Item             | Definição                                                                           |
| ---------------- | ----------------------------------------------------------------------------------- |
| Estilo           | API REST, corpos em JSON (`Content-Type: application/json`)                         |
| URL base         | Configurada no frontend por `VITE_API_BASE_URL`                                     |
| Identificadores  | Inteiros gerados pelo banco (MySQL, autoincremento via Prisma)                      |
| Datas            | Texto no formato ISO 8601, em UTC (ex.: `2026-11-18T12:00:00.000Z`)                 |
| Autenticação     | Token JWT devolvido no login e enviado no cabeçalho `Authorization: Bearer <token>` |
| Rotas públicas   | Cadastro, login, busca de jogos e detalhes de jogo                                  |
| Rotas protegidas | Dados do usuário logado e todas as operações de avaliação                           |
| Senha            | Nunca é devolvida em nenhuma resposta; armazenada apenas como hash                  |

### Formato padrão de erro

Todos os erros seguem o formato padrão do NestJS:

```json
{
    "statusCode": 400,
    "message": ["nota deve estar entre 0 e 10"],
    "error": "Bad Request"
}
```

`message` pode ser um texto ou uma lista de textos (erros de validação dos DTOs vêm em lista).

| Código             | Uso                                                                              |
| ------------------ | -------------------------------------------------------------------------------- |
| `400 Bad Request`  | Dados de entrada inválidos (campo vazio, formato errado, nota fora do intervalo) |
| `401 Unauthorized` | Credenciais inválidas no login, ou token ausente/inválido em rota protegida      |
| `404 Not Found`    | Recurso inexistente (jogo ou avaliação)                                          |
| `409 Conflict`     | Violação de unicidade (e-mail, nome de usuário ou avaliação duplicada)           |
| `503 Service Unavailable` | Fonte externa de jogos temporariamente indisponível |

## Módulo Usuários/Autenticação

### `POST /auth/register` — Criar conta (HU01)

**Entrada:**

```json
{
    "nome": "Ana Souza",
    "email": "ana@email.com",
    "username": "anasouza",
    "senha": "minhasenha123"
}
```

| Campo      | Regra                                                   |
| ---------- | ------------------------------------------------------- |
| `nome`     | Obrigatório, não vazio                                  |
| `email`    | Obrigatório, formato de e-mail válido, único no sistema |
| `username` | Obrigatório, não vazio, único no sistema                |
| `senha`    | Obrigatória, não vazia                                  |

**Saída `201 Created`:**

```json
{
    "id": 1,
    "nome": "Ana Souza",
    "email": "ana@email.com",
    "username": "anasouza",
    "criadoEm": "2026-11-18T12:00:00.000Z"
}
```

**Erros:**

| Código | Situação                                              |
| ------ | ----------------------------------------------------- |
| `400`  | Campo obrigatório vazio ou e-mail em formato inválido |
| `409`  | E-mail já cadastrado                                  |
| `409`  | Nome de usuário já cadastrado                         |

O cadastro não inicia sessão; o usuário faz login em seguida.

---

### `POST /auth/login` — Fazer login (HU02)

**Entrada:**

```json
{
    "login": "anasouza",
    "senha": "minhasenha123"
}
```

`login` aceita o e-mail ou o nome de usuário.

**Saída `200 OK`:**

```json
{
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "usuario": {
        "id": 1,
        "nome": "Ana Souza",
        "username": "anasouza"
    }
}
```

**Erros:**

| Código | Situação                                                                       |
| ------ | ------------------------------------------------------------------------------ |
| `400`  | `login` ou `senha` vazios                                                      |
| `401`  | Credenciais inválidas (mesma mensagem para usuário inexistente e senha errada) |

---

### `GET /auth/me` — Dados do usuário logado (HU02)

Usado pelo frontend para confirmar que a sessão é válida e liberar as ações restritas.

**Cabeçalho:** `Authorization: Bearer <token>`

**Saída `200 OK`:**

```json
{
    "id": 1,
    "nome": "Ana Souza",
    "email": "ana@email.com",
    "username": "anasouza"
}
```

**Erros:**

| Código | Situação                            |
| ------ | ----------------------------------- |
| `401`  | Token ausente, inválido ou expirado |

## Módulo Catálogo

A pesquisa usa a IGDB v4. Cada resultado tem um ID numérico local do Vorgame, usado nos detalhes e nas avaliações. Os jogos fictícios da carga inicial continuam acessíveis pelo ID local e fora dos resultados da pesquisa. Não há endpoints para criar, editar ou excluir jogos.

### `GET /games?q={termo}` — Pesquisar jogos (HU03)

**Entrada:** parâmetro de consulta `q`, com o termo buscado. Entre os resultados da IGDB, a API retorna os títulos que contêm o termo, sem diferenciar maiúsculas de minúsculas.

Exemplo: `GET /games?q=zelda`

**Saída `200 OK`:**

```json
{
    "resultados": [
        {
            "id": 7,
            "titulo": "The Legend of Zelda: Breath of the Wild",
            "capa": "https://exemplo.com/capas/botw.jpg",
            "mediaAvaliacao": 9.4,
            "totalAvaliacoes": 12
        }
    ]
}
```

Quando nenhum jogo é encontrado, a resposta é `200` com `"resultados": []`; o frontend exibe a mensagem de "nenhum jogo encontrado".

**Erros:**

| Código | Situação                       |
| ------ | ------------------------------ |
| `400`  | Parâmetro `q` ausente ou vazio |
| `503`  | Fonte externa de jogos indisponível |

Quando faltar uma capa em um jogo novo, `capa` é um texto vazio. Em jogos já cadastrados, metadados indisponíveis na IGDB mantêm os valores gravados.

---

### `GET /games/{id}` — Visualizar detalhes de um jogo (HU04)

Rota pública. A exibição de reviews está adiada para a entrega da HU06, por isso a resposta não traz reviews.

**Saída `200 OK`:**

```json
{
    "id": 7,
    "titulo": "The Legend of Zelda: Breath of the Wild",
    "capa": "https://exemplo.com/capas/botw.jpg",
    "descricao": "Aventura em mundo aberto...",
    "genero": "Aventura",
    "plataformas": ["Nintendo Switch", "Wii U"],
    "mediaAvaliacao": 9.4,
    "totalAvaliacoes": 12
}
```

Os detalhes são lidos do banco local, inclusive quando a IGDB está indisponível. Metadados ausentes de um jogo novo aparecem como texto vazio ou, no caso de `plataformas`, lista vazia. Quando o jogo ainda não tem avaliações no Vorgame, `mediaAvaliacao` é `null` e `totalAvaliacoes` é `0`. A média é exibida com uma casa decimal.

**Erros:**

| Código | Situação                     |
| ------ | ---------------------------- |
| `400`  | `id` não é um número inteiro |
| `404`  | Jogo não encontrado          |

## Módulo Avaliações

Regras comuns a todas as rotas deste módulo:

- Todas exigem `Authorization: Bearer <token>`.
- A nota é um número inteiro de 0 a 10.
- Cada usuário tem no máximo uma avaliação por jogo, garantida por restrição única (usuário + jogo) no banco.
- Gravar a nota e recalcular a média do jogo acontecem na mesma transação.

### `GET /games/{id}/ratings/me` — Consultar a própria nota (HU04, HU05)

Usado pela página do jogo para saber se o usuário logado já avaliou e qual ação mostrar (avaliar ou alterar nota).

**Saída `200 OK`:**

```json
{
    "jogoId": 7,
    "nota": 8,
    "atualizadoEm": "2026-11-18T12:30:00.000Z"
}
```

**Erros:**

| Código | Situação                                                      |
| ------ | ------------------------------------------------------------- |
| `401`  | Token ausente ou inválido                                     |
| `404`  | Jogo não encontrado, ou o usuário ainda não avaliou este jogo |

---

### `POST /games/{id}/ratings` — Avaliar jogo (HU05)

**Entrada:**

```json
{
    "nota": 8
}
```

**Saída `201 Created`:**

```json
{
    "jogoId": 7,
    "nota": 8,
    "mediaAvaliacao": 9.3,
    "totalAvaliacoes": 13
}
```

**Erros:**

| Código | Situação                                                                             |
| ------ | ------------------------------------------------------------------------------------ |
| `400`  | Nota ausente, não inteira ou fora do intervalo 0 a 10                                |
| `401`  | Token ausente ou inválido                                                            |
| `404`  | Jogo não encontrado                                                                  |
| `409`  | O usuário já avaliou este jogo; para mudar a nota, usar `PUT /games/{id}/ratings/me` |

---

### `PUT /games/{id}/ratings/me` — Alterar a própria nota (HU05)

**Entrada:**

```json
{
    "nota": 10
}
```

**Saída `200 OK`:**

```json
{
    "jogoId": 7,
    "nota": 10,
    "mediaAvaliacao": 9.5,
    "totalAvaliacoes": 13
}
```

`totalAvaliacoes` não muda ao alterar uma nota, apenas a média.

**Erros:**

| Código | Situação                                                                    |
| ------ | --------------------------------------------------------------------------- |
| `400`  | Nota ausente, não inteira ou fora do intervalo 0 a 10                       |
| `401`  | Token ausente ou inválido                                                   |
| `404`  | Jogo não encontrado, ou o usuário ainda não avaliou este jogo (usar `POST`) |
